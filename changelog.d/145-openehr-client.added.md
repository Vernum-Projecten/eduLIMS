eduLIMS signs in to FerroEHR as its own client with an OAuth2 client credentials grant, so four new settings are required before the server starts: `FERROEHR_TOKEN_URL` (the identity provider's token endpoint), `FERROEHR_CLIENT_ID` and `FERROEHR_CLIENT_SECRET` (the confidential client registered for eduLIMS there) and `FERROEHR_SCOPE` (the SMART on openEHR `system/` scopes it asks for; see `.env.example`). Upgrade step: register the client at your identity provider and add the four values to `.env` before you pull the new release; the B3 integration check keeps checking FerroEHR without a credential.
