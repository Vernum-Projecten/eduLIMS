- The account deletion endpoints of the sign-in library (`/api/auth/admin/remove-user`, `/api/auth/delete-user` and its callback) answer 404. `remove-user` deleted a user's sessions and sign-in links before it checked whether the user was the only teacher of a simulation, so a refused deletion could lock that teacher out (D10). eduLIMS now deletes a user in one step that changes nothing when it is refused, and never deletes the last administrator; the GDPR erasure path (#47) will use it.
