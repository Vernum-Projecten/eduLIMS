This document says how AI tools are used to develop eduLIMS, what they do and
do not touch, who is accountable, and which controls bound the work. It
follows the project principle **"AI ondersteunt, mens beslist"** (AI assists,
a person decides) from the architecture model, view 0.

The key words **shall**, **should** and **may** mean requirement,
recommendation and permission.

## 1. Scope

This document covers the use of AI tools to build everything in this
repository: application code, tests, CI/CD, infrastructure files and
documentation.

**eduLIMS ships no AI.** No model is trained, embedded or called while the
application runs. The optional plausibility check on measured values (D7) is
a rule-based range check. If the research group later wants an AI function
inside the application, that function processes real data and first needs a
GDPR (AVG) check and a model that runs inside Hanze (Adviesrapport, advice 2).

## 2. Terms

The levels follow the W3C AI Content Disclosure vocabulary: **none**
(written by a person), **ai-assisted** (written by a person, AI edited or
filled in boilerplate), **ai-generated** (generated by AI on a person's
prompt and reviewed by that person), **autonomous** (generated by AI without
meaningful human oversight).

## 3. Accountability

The maintainer ([MAINTAINERS.md](MAINTAINERS.md)) is the author of and
accountable for every change, whatever tool produced it. A tool **shall not**
be named as author, co-author or signer of a commit, pull request, issue or
file ([ADR 0009](docs/adr/0009-no-ai-attribution-human-review.md)). This
document is the single disclosure.

## 4. Where AI is used

The tool is an agentic coding assistant (Claude Code), used in sessions the
maintainer directs, reads and merges. `CLAUDE.md` and the rules under
`.claude/` give each session the same context: the architecture, the
requirements, the Definition of Done and the privacy rules.

| Activity | Level | Notes |
|---|---|---|
| Application code and tests | ai-generated | written in directed sessions, reviewed and merged by the maintainer |
| CI/CD and infrastructure files | ai-generated | the same review and gates |
| Documentation | ai-assisted | translated and edited from the maintainer's own coursework documents |
| Requirements, priorities, architecture decisions | none | decided by the product owner and the maintainer, recorded in `docs/` |
| Review verdicts and release decisions | none | made by people; see section 7 |

No row is **autonomous**.

## 5. Human review

Every change, whoever or whatever wrote it, goes through a pull request and
the merge queue, and merges only with green CI. By convention the supervising
teacher reviews the pull request, and the maintainer resolves every comment
before merging ([GOVERNANCE.md](GOVERNANCE.md#merging)). The maintainer keeps
track of how many AI-written pull requests needed changes in review, as input
for the retrospective (Teststrategie, "Het AI-onderdeel testen").

## 6. Controls

- **Tests and coverage.** Unit, data and integration tests run on every pull
  request; the core keeps at least 70% coverage (Q-MAINT-1).
- **Static checks.** TypeScript 7 type checking and Biome lint run on every
  change.
- **Dependency and image scanning.** CI scans dependencies and the container
  image; images are rebuilt monthly (R-05).
- **Accessibility.** axe runs in the Playwright tests (Q-ACC-1).
- **Secrets.** Passwords and keys never appear in code. They live in GitHub
  Actions secrets and in the VM's environment.
- **Tests are not weakened.** Nobody, person or tool, weakens, skips or
  deletes a test to make a build pass.

## 7. Prohibited uses

In this project, AI **shall not** merge anything, approve or review a pull
request as the deciding reviewer, decide a requirement or its priority, or
weaken a test or a gate.

## 8. Data

AI tools see code and the pseudonymised test set only. They **shall not**
receive real names, student numbers, grades or measurements of real people.
The development and test databases hold only that test set, so a prompt
cannot contain real personal data by accident. This rule is also in
`CLAUDE.md`.

## 9. Licensing

eduLIMS is licensed under Apache-2.0. AI output is held to the same
originality bar as code a person writes: substantially copied third-party
material is refused or licensed properly, and third-party code that is
copied in on purpose (such as the shadcn/ui components) is recorded in
[REUSE.toml](REUSE.toml).

## 10. Sustainability

AI use costs energy. The tools are used during development only, never in the
running application, and with short, focused tasks instead of rewriting whole
files (Adviesrapport, advice 2).

## 11. Review and change

The maintainer reviews this statement at every minor release, and earlier
when the tooling changes, a vendor's terms change, a binding rule appears
(for example under the EU AI Act or Hanze policy), or a claim in this document
stops being true. A change lands as a pull request, with the version below
updated.
